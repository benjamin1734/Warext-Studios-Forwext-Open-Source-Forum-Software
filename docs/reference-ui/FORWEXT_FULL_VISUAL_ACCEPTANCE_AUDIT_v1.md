# Full reference visual acceptance: findings and remaining proof

Review basis: 562 indexed UI reference screenshots in `FORWEXT_UI_REFERENCE_INDEX_v5.txt` and their logical page groups in `FORWEXT_UI_PAGE_MAP_v5.txt`. This is an evidence-based comparison, **not a declaration of pixel parity**. External product names are intentionally omitted.

## Evidence collected

- Reference screenshot inventory: 562 items (129 JPEG and 433 PNG).
- Installed application screenshot capture: 62 named first-party route/state scenarios at desktop 1440px and mobile 390px, with 15 high-priority pages additionally captured at tablet 768px and compact desktop 1024px (154 installed screenshots total).
- Screenshot artifacts and a JSON index are generated by `tools/browser/visual-review-capture.mjs` from a freshly installed MySQL-backed runtime. They can be downloaded from the qualification-matrix Actions run.
- Each reference belongs to a route/page group but a route screenshot is **not** evidence of the specific reference image's selected tab, open dialog, form contents, hover state, authenticated permissions or list data.
- Canonical legal routes are `/help/contact`, `/help/terms` and `/help/privacy`. Stale routes in the reference index/page map were corrected by the actual runtime audit. Oversight-case screens must resolve a real case link from the installed fixture, not a fabricated static identifier.

## Acceptance contract

The automated browser gate can prove route response health, mobile viewport reflow and that a screenshot was actually captured from an installed runtime. It **cannot** prove all 562 UI states are visually equivalent.

For actual final visual signoff, associate each REF ID with its authentic live route + explicit user/data/permission state, capture the exact control/tab/dialog at comparable scale, record discrepancies and fixes, and review the **before/after** at full resolution. Mark each image as accepted only after that comparison. Do not mark noncaptured forms and legacy-route 404 pages as accepted merely because broad CI workflows pass.

The parent release v1.0.19 passed package/security functional qualification; reference-level visual acceptance is an additional product-quality gate that is still open.
