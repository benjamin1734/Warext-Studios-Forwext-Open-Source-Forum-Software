# 07.07 — Realtime Notification Delivery

- Connected the notification engine to the existing 03.06 realtime message infrastructure instead of introducing a second queue or WebSocket stack.
- Added native browser transport fallback: WebSocket → SSE → database-backed polling, with polling always available for minimum cPanel deployments.
- Reused durable realtime `sequence_id` values as resume cursors so grouped notification updates remain observable without timestamp ambiguity.
- Added recipient-derived channels (`notification.user.<user-id>`) and actor-scoped canonical snapshot reads; clients cannot select an arbitrary user/channel to read another account's notifications.
- Kept gateway wake payloads minimal (`notification_id` only). Notification title, body, action and private payload are fetched again through the authorized backend path.
- Added notification publish hooks after durable mutation/delivery enqueue; dedupe hits do not generate duplicate wakes and realtime provider failure cannot roll back the canonical notification.
- Added authenticated polling and SSE endpoints, bounded cursor/limit handling, private/no-store response semantics, same-origin WebSocket path constraints and base-path-aware native frontend URLs.
- Added the native `notification-realtime.js` client with visual/ARIA delivery, a `forwext:notification` event and supplementary integration with the 07.06 sound player.
- No migration was required because the durable sequence store and transport abstractions already exist from 03.06.
- Added realtime publisher privacy, recipient-scope/IDOR and native transport-fallback regression tests plus architecture documentation.
