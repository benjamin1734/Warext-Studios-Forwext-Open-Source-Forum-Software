# 09.05 — Anti-Spam / Abuse Tools

Implemented the shared first-party flood, spam-cleanup and automated abuse-rule system.

- Added typed registration/thread/post abuse events with user, identity, IP, device and content signals.
- Added privacy-safe fixed-window counters and editable review/reject rules.
- Added conservative first-party default rules for registration IP/device, thread user/device/content and post user/device/content abuse.
- Kept raw IP, e-mail and user-agent values out of the anti-abuse tables.
- Added `AbuseRequestContextFactory` so authenticated HTTP layers can reuse existing HMAC authentication fingerprints for IP/device signals.
- Integrated registration review/reject behavior with existing registration state transitions.
- Integrated thread/post review decisions with the existing pending moderation states and 09.03 approval queue.
- Reject decisions stop thread/post persistence before content is written.
- Added native `/moderation/abuse` management UI and an Anti-spam Moderation Workspace section.
- Added granular view/rule-management/cleanup permissions.
- Added bulk spam cleanup through `ContentModerationService`; normal forum bulk/delete permissions remain mandatory.
- Cleanup, abuse-event resolution and audit persistence share one outer transaction.
- Added same-origin mutation protection, HTML escaping and moderation-audit integration.
- Added additive migration `20260918004000_abuse_prevention`.
- Added bounded scheduled retention cleanup for stale counters and old resolved abuse events; unresolved review items are preserved.
- Added regression coverage for rule thresholds/severity, privacy-safe request contexts, registration approval forcing, thread/post review hooks, permission catalog/migration registration and escaped native UI.
