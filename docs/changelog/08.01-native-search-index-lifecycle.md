# 08.01 — Native Search / Index Lifecycle

- Added a permission-aware native search index lifecycle on top of the existing MySQL FULLTEXT driver instead of introducing a second search stack.
- Added `forum`, `thread`, `post` and `user` first-party index sources with source-state validation; pending/rejected/deleted content and private user fields are excluded from index documents.
- Added stable search visibility scopes and actor-side scope resolution. Forum/thread/post documents are restricted by node `forum.view`; public user documents expose username-only searchable data.
- Added durable `forwext_search_index_outbox` processing with bounded leases, retry/backoff and idempotent upsert/delete semantics so provider/index failures do not roll back canonical content writes.
- Added MySQL lifecycle triggers for forum nodes, threads, posts and users. Thread visibility/node/title/state changes also requeue dependent posts so stale scopes/content are rebuilt.
- Added `BEFORE DELETE` thread handling so dependent post index entries are explicitly queued for removal before database cascades can erase the source rows.
- Kept `unlisted` forum nodes out of search discovery while preserving permission-aware indexing for visible nodes.
- Added the shared `search.use` permission namespace entry and actor-bound access-scope resolver instead of trusting client-provided scope tokens.
- Added cPanel-friendly maintenance integration for draining the search outbox without requiring Redis, Supervisor, Node.js or a dedicated daemon.
- Registered migration `20260917003000_search_index_lifecycle` and added clean-install verification for the outbox and lifecycle triggers.
- Added lifecycle service, source privacy/visibility, migration/trigger, access-scope and registry regression tests plus architecture documentation.
