# 11.01 — Bug Report Domain and Workflow

Implemented the production bug-report core required by roadmap sub-step 11.01.

- Added typed `new`, `in_review`, `resolved`, `rejected`, and `duplicate` workflow states.
- Added low/medium/high/critical severity and configurable bug categories with default severity.
- Added immutable bug-report aggregate with reporter, optional assignee, terminal finalized timestamp, UTC timestamps, and optimistic-lock version.
- Added permission-aware create/own/all access plus category, severity, lifecycle, and assignment operations.
- Added dedicated `bug.report.assign` permission and assignee validation against `bug.report.view_all`.
- Added backend IDOR/BOLA protection for single-report/history access and all staff mutations.
- Added append-only public/staff tracking history for creation, status, assignment, severity, and category changes.
- Added additive migration `20260918021000_bug_report_workflow` with category/report/history tables, indexes, foreign keys, starter categories, and permission-template defaults.
- Added regression coverage for category defaults, cross-user access denial, assignee authorization, terminal/reopen behavior, history visibility, category/severity changes, and duplicate lifecycle rules.
- Technical diagnostic context remains 11.02; form/attachments 11.03; reporter UI 11.04; duplicate detection/dashboard/search/export/audit 11.05.
