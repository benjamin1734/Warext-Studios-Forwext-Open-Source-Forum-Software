# 10.03 — Support Conversation and Staff Tools

Implemented the support conversation/staff-tool layer required by roadmap step 10.03.

- Added append-only requester/staff public messages and staff-only internal notes.
- Added backend own-vs-all visibility enforcement and granular permissions for staff reply, notes, assignment, escalation, merge, split and canned-response management.
- Added reusable canned responses with immutable key/title snapshots on historical messages.
- Added first-response SLA recording on the first staff public reply.
- Added automatic resolved-to-open reopening when a valid reply resumes a ticket.
- Added append-only public/staff workflow history for creation, status, assignment, escalation, merge, split and first response.
- Added monotonic escalation levels 1-5 with a database-level concurrent downgrade guard.
- Added non-destructive same-requester merge: source closes, messages copy with provenance, originals remain intact and a typed relation links both tickets.
- Added safe split from public messages only; internal notes cannot leak into a new requester-visible ticket.
- Added durable notifications for staff replies, requester replies to assignees, assignment, status changes and split-created tickets.
- Added native permission-aware `/support/tickets/{ticketId}` conversation/staff-tools route.
- Added ticket-authorized private support attachment downloads with persisted size/SHA-256 integrity verification.
- Added migration `20260918013000_support_conversation_tools`, permission-template defaults and regression coverage.
- FAQ remains 10.04-10.05; My Tickets/staff dashboard/SLA reporting/support audit remain 10.06.
