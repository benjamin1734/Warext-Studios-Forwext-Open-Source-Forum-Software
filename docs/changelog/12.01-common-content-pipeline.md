# 12.01 — Common Content Pipeline

Implemented the shared first-party content-processing contract.

## Added

- Canonical `validation → spam → spellcheck → AI moderation → moderation policy → persist → notify → index` stage definition.
- Pipeline engine that requires one processor for every pre-persist stage and rejects duplicate/missing registrations.
- Strict default validation for UTF-8, control characters, empty content and operation byte limits.
- Existing `AbuseEngine` adapter as the spam stage.
- Review propagation through a typed pipeline context.
- After-persist abuse event finalization with the real thread/post id.
- Explicit spellcheck and AI moderation pass-through processors for the 12.04 and 12.02 extension points.
- Transactional persist/notify/index orchestration.
- Search-index-change adapter using the existing durable search lifecycle queue.
- First-party forum pipeline factory.
- Thread creation, post creation/reply and post-edit pipeline integration.
- Regression coverage for canonical stage order, transaction rollback, registry completeness, forum review behavior and search-change enqueue.

## Compatibility and security

- Existing backend forum permissions remain authoritative.
- Existing anti-abuse reject behavior still stops persistence.
- Review decisions continue to place content in moderation.
- Post edits can no longer bypass the common pipeline when it is configured.
- Search queue writes happen in the same transaction as persistence.
- No new schema or permission migration is required.

## Roadmap boundary

12.01 does not implement AI providers or a spellchecker.

- AI provider/risk/fallback/human-override behavior: **12.02**.
- AI privacy, secrets, prompt and cost controls: **12.03**.
- Turkish-first spellchecking and dictionaries: **12.04**.
