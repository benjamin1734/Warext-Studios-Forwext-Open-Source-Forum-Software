# 09.06 — Core Moderator/Admin Audit

Implemented the shared operational audit stream required by the roadmap.

- Added extensible core audit events with scope, actor, action, target, optional forum/reason context, request id, before/after snapshots and UTC occurrence time.
- Added central `forwext_core_audit_events` persistence and target/actor/request/time indexes.
- Added recursive persistence-time sensitive-data redaction for secrets, credentials, auth/session material, raw IPs and e-mail values.
- Added transaction-only database writes and `AuditRecorder` mutation wrapping so state and audit records commit atomically.
- Adapted the existing moderation audit store to the central stream without changing existing moderation-domain APIs.
- Added an upgrade-safe import from the previous moderation audit table while replacing legacy snapshot JSON with a redaction marker.
- Added `audit.view` built-in template defaults and a permission-gated native `/moderation/audit` viewer with actor/request-id filters.
- Added a conditional Core Audit Stream link to the Moderation Workspace.
- Integrated the existing `ForumMetadataAdminService` with mandatory administration-scope audit recording for ACP metadata changes.
- Added regression coverage for redaction, transaction enforcement, audit-view permission checks, admin before/after/request-id capture and central moderation persistence.
- Kept tamper-evident/hash-chain independent oversight out of this step; that remains 09.07.
