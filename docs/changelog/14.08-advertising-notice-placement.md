# 14.08 — Advertising / Notice / Placement System

- Added first-party advertisement, notice and announcement campaign types.
- Added stable native placement keys for site, content and thread surfaces.
- Added route wildcard, forum, user-group, desktop/mobile and UTC time-window targeting.
- Added HMAC-based authenticated/anonymous frequency identities and rolling impression caps.
- Added fail-open HTML response decoration so advertising runtime failures cannot turn healthy forum pages into 500 responses.
- Added tracked campaign click redirects with relative/HTTPS destination policy and rapid-repeat analytics de-duplication.
- Added privacy-bounded impression/click events and 30-day CTR plus estimated revenue/value reporting.
- Added real forum/group selection in the native administration UI rather than requiring raw internal ids.
- Added backend `ads.manage` / `notice.manage` enforcement, dedicated CSRF and central administration audit records.
- Added migration `20260921223000_advertising_notice_system` for campaigns, four targeting dimensions and indexed analytics/frequency events.
- Added domain, web-wiring, migration-registry, targeting/frequency and click-dedupe regression tests.
- Added architecture documentation at `docs/architecture/advertising-notice-placement.md`.
