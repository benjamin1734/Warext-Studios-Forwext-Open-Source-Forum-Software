# 10.02 — Ticket Creation UX and Form System

Implemented the production ticket-intake flow required by roadmap step 10.02.

- Added category-specific dynamic text, textarea, select and checkbox field definitions with backend required/type/choice/length enforcement.
- Added description and historical dynamic-field value persistence.
- Added typed thread/account/marketplace context links.
- Thread context verifies real forum view access; account context is self-only unless the actor has support staff all-ticket access.
- Marketplace context stores an opaque canonical listing reference without exposing unavailable marketplace data before that module exists.
- Added support-specific private attachment metadata while reusing the shared verified-upload reader, attachment inspector, filename normalization and storage driver.
- Added storage compensation when database submission fails.
- Added fixed-window per-user hourly/daily and duplicate-content anti-spam limits using SHA-256 fingerprints only.
- Added native authenticated `GET|POST /support/new` UX with dedicated CSRF scope and progressive context disclosure.
- Added additive migration `20260918012000_support_ticket_intake` for field definitions, intake, values, context links, attachments and rate-limit buckets.
- Added regression coverage for field manipulation, duplicate rate limiting, attachment persistence and form HTML escaping.
