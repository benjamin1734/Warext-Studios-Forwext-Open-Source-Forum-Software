# 20.05 — CI ve otomatik test matrisi

Version: `0.0.7.67-dev`

## Delivered

- Added the read-only `Qualification test matrix` GitHub Actions workflow with PHP 8.4 and PHP 8.5 jobs.
- Added explicit acceptance slices for unit/integration behavior, API v1, native web/browser surfaces, first-party module runtime, the shipped sample add-on, architecture rules and security regression contracts.
- Extended the MySQL 8.4 and MariaDB 10.11 migration workflow with incremental upgrade acceptance and installed first-party module ON/OFF runtime verification.
- Preserved the existing build/package workflow as the release-build authority for complete PHP tests, TypeScript SDK, React UI, official Next.js, PHP 8.4 production dependencies and full/update ZIP integrity.
- Added `QualificationMatrixPolicyTest` so the roadmap-required CI dimensions cannot be removed silently.

## Database qualification

- Clean migration remains required on both supported database families.
- The cPanel-first browser installer/post-install web bootstrap remains required on both database families.
- The upgrade smoke creates a temporary sibling CI database, applies all but the newest registered migration, then requires exactly one migration to apply when the full registry is executed.
- A final migration pass must be completely idempotent.
- The installed module smoke persists Marketplace as disabled, requires the route to fail closed with HTTP 503, re-enables it and requires a usable route. The original state is restored in a `finally` block.

## Security and runtime impact

- Qualification workflows have read-only GitHub contents permission and cannot publish a release.
- The temporary upgrade database name is strictly validated before identifier interpolation and is dropped in a `finally` block.
- Module toggling operates only on the CI database produced by the immediately preceding installer smoke.
- No production dependency, daemon or service requirement was added. Composer, PHPUnit and Node remain development/build tooling only.
