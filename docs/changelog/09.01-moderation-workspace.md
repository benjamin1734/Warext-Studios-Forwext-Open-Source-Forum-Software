# 09.01 – Moderation workspace

Implemented the first-party internal moderation workspace foundation.

- Added a permission-gated `/moderation` workspace with reports, approval, warnings, bans and tasks sections.
- Added a provider/read-model contract so later moderation domains feed the same workspace instead of creating parallel dashboards.
- Added real pending thread/post visibility using server-derived forum nodes and existing node-scoped `forum.view`, `forum.thread.moderate` and `forum.post.moderate` permissions.
- Added persistent moderator tasks with priority, status, optional assignee and optional UTC due date.
- Added transactional task audit events through the existing moderation audit store.
- Added same-origin mutation protection using the configured canonical origin plus `X-Forwext-Moderation`.
- Added migration `20260918001000_moderation_workspace_tasks`; upgrades remain data-preserving and idempotent.
- Added native PHP UI, XSS escaping, `no-store`/`noindex` responses and regression tests.

The detailed report lifecycle (09.02), cross-domain approval queue behavior (09.03), and warning/discipline/ban domain (09.04) remain separate planned work. Empty workspace sections are real integration points and do not fabricate data.
