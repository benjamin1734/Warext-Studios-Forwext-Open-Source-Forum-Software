# Forwext 1.0.4 — Native forum authoring pass

This production-acceptance remediation release turns the native forum browsing surface into a usable write workflow.

## Added

- Native PHP **Yeni konu** workflow at `/forums/{slug}/new-thread`.
- Native PHP **Yanıtla** workflow at `/threads/{threadId}/reply`.
- Permission-aware action buttons on forum and thread pages.
- Dedicated responsive composer surfaces using the existing Forwext design-token/component system.
- CSRF protection for both authoring endpoints.
- Validation feedback without discarding the submitted title/body.
- Moderation-aware redirects for newly created threads and replies.

## Domain and security integration

- Thread creation is performed through `ThreadCreationService` + `ThreadPublishingService`; the public handler does not bypass forum domain rules.
- Reply creation is performed through `PostService::reply()`.
- Existing `forum.thread.create` and `forum.post.create` permissions remain authoritative.
- Forum visibility, new-thread/reply settings, locked-thread state and thread-type reply capability remain enforced by the existing domain layer.
- New content continues through the shared content pipeline, including validation, abuse/spellcheck/moderation policy stages and search-index change recording.
- Unsafe POST requests are rejected by the existing CSRF middleware.

## Acceptance and regression coverage

- Added a public forum-writing web-surface regression test covering route wiring, CSRF, permission checks, domain-service usage, content-pipeline usage, moderation-aware redirects and composer UI markers.
- Qualification matrix, database migration smoke, security qualification and performance/observability qualification passed for the implementation commit before release packaging.
- No schema migration is required.

## Production acceptance status

Native forum discovery, reading, thread creation and reply workflows now have first-class native PHP surfaces.

Production acceptance remains open. The next remediation pass is authentication/account entry UX and then the remaining notification/social/ACP/module native UI parity work.
