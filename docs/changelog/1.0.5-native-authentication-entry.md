# Forwext 1.0.5 — Native authentication entry pass

This production-acceptance remediation release adds the first native account-entry surface to the public PHP frontend.

## Added

- Native PHP login workflow at `/login`.
- Native PHP logout confirmation/workflow at `/logout`.
- Guest/member authentication actions in the shared responsive navigation.
- Dedicated native authentication styling integrated with the existing Forwext design-token/component system.
- A database-backed MFA user-group provider so the existing strictest-group MFA policy can be composed in the public runtime.

## Security integration

- Login reuses the existing `AuthenticationService`; it does not duplicate credential verification.
- Existing password hashing/rehash policy, DB-backed identity/network rate limiting, login history, device tracking and discipline-based account availability remain authoritative.
- Client IP resolution uses the existing trusted-proxy/Cloudflare CIDR model instead of trusting forwarded headers directly.
- Login and logout forms are protected by a dedicated CSRF intent/namespace.
- Successful login issues the configured `__Host-` session cookie as Secure + HttpOnly + SameSite=Lax.
- Logout revokes the server-side session before expiring the browser session cookie.
- MFA-required accounts fail closed: primary credentials do not create an authenticated session when `SecondFactorRequiredException` is raised.

## Acceptance and regression coverage

- Added native auth web-surface regression coverage for route/CSRF wiring, AuthenticationService composition, security services, secure session cookies, logout revocation and MFA fail-closed behavior.
- PHP 8.4 and PHP 8.5 qualification passed.
- Security qualification passed.
- MySQL 8.4 and MariaDB 10.11 migration smoke passed.
- Shared-hosting performance/observability qualification passed.
- Full package validation passed, including strict-types, PHP lint, PHPUnit 8.4/8.5, SDK, React UI and official Next.js builds.
- No database migration is required.

## Remaining production-acceptance work

This pass intentionally does not bypass or weaken unfinished MFA/account flows. Native MFA challenge completion, registration, email verification/password recovery and the remaining account/notification/social/ACP/module surfaces remain open for the next remediation passes.
