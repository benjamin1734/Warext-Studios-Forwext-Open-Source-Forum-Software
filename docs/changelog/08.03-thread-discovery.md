# 08.03 — New, unread, trending, featured and recent discovery

- Added typed discovery modes and a dedicated thread discovery service/repository boundary.
- Reused server-derived search/forum access scopes so discovery requires `search.use` and only forums already authorized through `forum.view` are queried.
- Added a single aggregate SQL path for visible active threads, visible post activity and existing thread/forum read state; no per-thread unread N+1 loop is required.
- Added deterministic new/unread/featured/recent ordering and a bounded seven-day trending activity window.
- Reused the existing `featured` thread state rather than creating duplicate feature metadata.
- Added idempotent migration `20260917230000_discovery_query_indexes` for thread/post discovery indexes and registered it in the clean-install migration registry.
- Added tests for scope deduplication, permission denial, unread SQL/read-state semantics, pagination and trending-window ordering.
