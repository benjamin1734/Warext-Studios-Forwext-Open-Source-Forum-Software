# 15.01 — Analytics Event Model

- Added a privacy-aware analytics event registry covering forum, user, content, support, bug, Marketplace, referral, giveaway and moderation domains.
- Added per-event identity collection policy, dimension allowlists and bounded retention periods.
- Added deterministic HMAC-SHA256 pseudonymization for actor, session and subject identities using a domain-separated installation key.
- Added strict dimension validation that rejects non-allowlisted keys, free-form string payloads and raw IP addresses.
- Added `forwext_analytics_events` persistence with event/category/forum/actor/subject/retention indexes and no raw IP, user-agent, e-mail, request URI or raw user-id fields.
- Added `AnalyticsEventRecorder` strict and best-effort write paths plus bounded per-definition retention pruning.
- Added daily analytics retention maintenance task/handler using the existing scheduler/maintenance queue model.
- Added native runtime production of `user.active` and `forum.view` after successful HTML GET responses, including thread-to-forum resolution and reuse of the bounded device classifier.
- Added migration `20260921230000_analytics_event_model` and core migration-registry coverage.
- Added unit/static regression coverage for registry domain completeness, pseudonymization, privacy allowlists, runtime wiring and retention behavior.
- Added architecture documentation at `docs/architecture/analytics-event-model.md`.
