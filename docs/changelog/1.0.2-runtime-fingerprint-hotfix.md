# Forwext 1.0.2 — Runtime fingerprint secret hotfix

This maintenance release fixes a post-install HTTP 500 that could occur on real browser requests after a successful fresh installation.

## Root cause

The browser installer persisted database/SMTP secrets but did not provision the operational fingerprint secrets referenced by:

- `authentication.fingerprint_key`
- `registration.fingerprint_key`

The normal post-install smoke request did not include a User-Agent header. A real browser does. When the Analytics middleware classified a real browser User-Agent, `AuthenticationFingerprint` attempted to read the missing authentication fingerprint secret and failed, turning an otherwise valid home-page response into an Internal Server Error.

## Fixed

- Added `RuntimeSecretBootstrapper` for the required fingerprint secrets.
- Fresh installs provision both fingerprint secrets before the installation is marked complete.
- Existing 1.0.1 installations self-heal the missing secrets from the existing master key without requiring a database reset or reinstall.
- Existing valid fingerprint secrets are preserved.
- Added regression coverage that exercises the browser User-Agent fingerprint path.
- Runtime failures continue to be written to `storage/logs/runtime.log` and are now also mirrored, sanitized, to the hosting PHP error log for easier cPanel diagnosis.

## Upgrade impact

- No database migration is required.
- No user/content data is reset.
- The 1.0.1 → 1.0.2 update package is sufficient for an existing installation.
- Fresh installations should use the 1.0.2 full package.
